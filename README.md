# Swaston Project — Telegram-платформа для исходного кода

Реализован рабочий модульный скелет под ТЗ: регистрация + CAPTCHA, подача исходников
(FSM-анкета), автопроверка архивов, модерация (подтвердить/отклонить/вирус/наказание),
публикация в канал, реакции лайк/дизлайк, каталог с фильтрами, профиль.

## Структура

```
swaston/
  config.py              — все настройки из переменных окружения
  main.py                 — точка входа
  database/
    base.py                — движок и сессии SQLAlchemy (async)
    models.py               — таблицы: users, submissions, reactions, comments,
                               virus_reports, sanctions, moderation_logs
    crud.py                 — функции доступа к данным
  services/
    roles.py                — иерархия ролей и проверки прав
    captcha.py               — математическая CAPTCHA
    validation.py            — проверка архивов (расширение/MIME/размер/ZIP-бомба/
                               directory traversal/ClamAV-хук)
    sanctions.py             — расчёт сроков банов
    notify.py                — отправка заявок модераторам, уведомления авторам
    publishing.py            — публикация одобренного поста в канал
  keyboards/               — inline/reply-клавиатуры
  handlers/
    start.py                 — /start, капча, правила, поддержка
    submission.py            — пошаговая анкета подачи исходника
    moderation.py            — approve/reject/virus/punish
    reactions.py             — лайки/дизлайки
    catalog.py                — каталог с фильтрами и пагинацией
    profile.py                — профиль пользователя
```

Роль хранится прямо в `users.role` — отдельной таблицы `moderators` не потребовалось,
это упрощает архитектуру без потери функциональности из ТЗ.

## Переменные окружения

Смотри `.env.example`. Обязательные: `BOT_TOKEN`, `CHANNEL_ID`, `MOD_GROUP_ID`, `OWNER_ID`.

**Важно про ID канала/группы:** Telegram API ожидает ID супергрупп и каналов в формате
`-100XXXXXXXXXX`. Если у тебя есть только числовой ID из deep-ссылки (`tg://chat?id=...`),
скорее всего нужно добавить префикс `-100` к этому числу. Самый надёжный способ проверить —
добавить бота в канал/группу админом, переслать любое сообщение оттуда боту-помощнику
(например @getidsbot) и свериться с тем ID, который он покажет.

## ⚠️ Токен бота

Токен, который ты прислал в чат, теперь считается скомпрометированным (он есть в истории
переписки). Перед продакшен-запуском зайди в @BotFather → `/mybots` → выбери бота →
Bot Settings → Revoke current token, и используй новый токен в переменной `BOT_TOKEN`.

## Настройка канала и группы обсуждений

1. Бот должен быть добавлен администратором в канал (`CHANNEL_ID`) — с правом публикации постов.
2. Бот должен быть администратором в закрытой группе модераторов (`MOD_GROUP_ID`).
3. Для системы комментариев (Telegram Discussions) — привяжи к публичному каналу отдельную
   группу обсуждений через настройки канала в самом Telegram (Channel Settings → Discussion).
   Это делается нативно средствами Telegram, кода не требует — комментарии и ответы будут
   доступны под каждым постом автоматически.

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
export $(cat .env | xargs)   # или использовать python-dotenv
python main.py
```

По умолчанию используется локальный SQLite (`swaston.db`), создаётся автоматически при
первом запуске.

## Деплой на Railway

1. Залей проект в GitHub-репозиторий.
2. В Railway: **New Project → GitHub Repository** → выбери репозиторий.
3. Добавь **PostgreSQL** (New → Database → PostgreSQL) в тот же проект.
4. Скопируй у PostgreSQL `DATABASE_URL` и в переменной окружения бота пропиши её с заменой
   префикса: `postgres://...` → `postgresql+asyncpg://...`
5. В Variables сервиса бота добавь: `BOT_TOKEN`, `CHANNEL_ID`, `MOD_GROUP_ID`, `OWNER_ID`,
   `DATABASE_URL`.
6. Railway увидит `Procfile` и запустит `python main.py`.

## О сканировании файлов

- Проверяются: расширение, MIME-тип, размер, корректность ZIP, подозрительные коэффициенты
  сжатия (защита от ZIP-бомб), пути с `../` или абсолютные пути (directory traversal).
- Загруженный код **никогда** не распаковывается в файловую систему целиком и не запускается
  на сервере — только читаются метаданные записей архива.
- ClamAV подключается опционально через `CLAMAV_HOST`/`CLAMAV_PORT` (нужен установленный
  `clamd` и пакет `pyclamd`, не входит в requirements.txt по умолчанию — поставь при необходимости:
  `pip install pyclamd`). Если не настроен — сканирование пропускается, это видно в логах
  и в карточке заявки модераторам.
- Результат сканирования — вспомогательный сигнал, не гарантия безопасности. Окончательное
  решение всегда принимает модератор вручную.

## Что доделать перед реальным продакшеном

- Alembic-миграции вместо `create_all` (который в `database/base.py` только для разработки).
- `MemoryStorage` для FSM аiogram подходит для одного процесса; при масштабировании на
  несколько инстансов — перейти на `RedisStorage`.
- Команды администратора для управления ролями (`/promote`, `/demote`) — сейчас роль можно
  менять только напрямую через БД; `OWNER_ID` бутстрапится автоматически при первом старте.
- Рейт-лимиты на подачу заявок (защита от спама анкетами).
